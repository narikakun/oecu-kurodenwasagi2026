# 黒詐欺電話

600-A2型黒電話のフックスイッチとロータリーダイヤルをRaspberry Pi 5で読み取り、USB受話器を通してGPT-Liveと音声会話する大学制作向けプロジェクトです。

設計の詳細は[設計書](docs/design.md)を参照してください。

## 音声会話

受話器を上げるとGPT-Liveとの接続を開始し、最初の音声入力より先に挨拶指示を送信して、
AIが「もしもし？」と一度だけ呼びかけます。GPT-Liveの音声タイムラインを止めないため、
挨拶処理中もマイク音声ストリームは継続します。挨拶指示の受理通知だけでは完了扱いにせず、
実際のAI音声と「もしもし」の文字起こしを確認してから通常会話へ移ります。5秒以内に
挨拶が届かなければ一度だけ再送し、それでも届かなければ接続エラーとして終了します。
受話器を置くと接続を終了します。

受話器が置かれているときにダイヤルを回すと、その数字と同じ秒数だけ待ってから、
GPT-Liveへ事前接続し、入力をミュートした状態でベル用スピーカーから
`Rotary_Phone-Ringtone01-1.mp3`を繰り返し再生します。
別の数字を回すと予約をやり直し、受話器を上げるとベルを止めてGPT-Liveへ接続します。
`0`は待ち時間なしでベルを鳴らします。

受話器を上げると事前接続済みのセッションの入力を有効にしてから挨拶を開始するため、
接続待ちを挟まず「もしもし？」を再生できます。設定画面へ移った場合やベルを止めた場合は、
事前接続したセッションも終了します。
GPT-Liveの接続開始、事前接続完了、通話開始、終了開始、終了完了はターミナルへログ表示します。

起動時には、受話器入力・受話器出力・ベル出力に設定されているデバイス番号と名前を
ターミナルへ表示します。ベルが鳴っている間にダイヤルを回すとベルを止め、音声
デバイス設定画面へ移ります。このとき最初に回した数字は項目選択には使われません。
設定中は会話欄を隠した専用画面に、設定項目または選択可能なデバイスを表示します。
最初の設定画面には現在の受話器入力・受話器出力・ベル出力も表示し、デバイスを変更すると
現在の設定を更新したうえで最初の設定項目選択へ戻ります。

1. 設定画面へ移った後、改めて`0`で受話器入力、`1`で受話器出力、`2`でベル出力を選びます。
2. ターミナルへ表示された有効なデバイスのうち、`0`～`9`の番号を回します。
3. 続けて別の項目を設定するか、受話器を上げると設定モードを終了します。

ダイヤルでデバイスを選ぶと、そのデバイスの既定サンプルレートを自動取得し、受話器入力・
受話器出力・ベル出力へ個別に適用します。適用した値は最初の設定画面に表示されます。

ダイヤルで選んだ設定は`AUDIO_SETTINGS_FILE`のJSONへ保存され、次回起動時にも復元されます。
デバイス番号は接続順で変わることがあるため、保存にはデバイス名を使用します。保存した
デバイスが起動時に見つからない、または選択した用途に対応していない場合は、その項目だけ
OSの既定デバイスへ戻します。保存先の初期値は
`~/.config/kuro-sagi-denwa/audio-settings.json`です。

## 必要な環境

- Raspberry Pi 5
- Raspberry Pi OS（64bit推奨）
- Python 3.11以上
- USB-C受話器（マイク・スピーカーとして認識されるもの）
- 600-A2型黒電話のフックスイッチとダイヤル接点
- OpenAI APIプロジェクトキーとGPT-Liveへのアクセス

## セットアップ

PortAudioなど、`sounddevice`が使うOSパッケージを入れます。

```bash
sudo apt update
sudo apt install -y python3-venv libportaudio2
```

仮想環境を作り、アプリをインストールします。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
```

`.env.example`をコピーし、APIキーなどを設定します。プロジェクト直下で起動すると`.env`が自動で読み込まれます。

```bash
cp .env.example .env
# エディタで.envを編集する
kuro-sagi-denwa
```

シェルですでに設定されている環境変数は`.env`より優先されます。systemd運用時は`EnvironmentFile`で指定したファイルが使われます。

GPT-Liveには、守口市役所の職員を名乗る還付金詐欺シナリオを設定しています。
22,560円の医療費還付、期限切れ、銀行・ATMでの特別手続きという順に会話し、参加者の
自由な返答から安全行動・危険行動・判断保留へ自然に分岐します。選択肢やクイズは読み上げず、
本名や口座情報を尋ねたり、具体的な送金操作を案内したりしません。詳細は
[還付金詐欺シナリオ](docs/fraud-scenario.md)を参照してください。
追加の会話スタイルを指定したい場合だけ`LIVE_INSTRUCTIONS`を設定します。
音声はデフォルトでNatural系の男性音声`meridian`を使用します。
会話は実際の電話に近い短いターン制です。発話は原則1〜2文、質問は一度に1つとし、
相づちや感想も使います。長い説明は分割し、参加者が話し始めたら聞くことを優先します。
シナリオ中の詳細確認はResponsesバックエンドやWeb検索へ委譲せず、設定済みの架空情報だけで
会話を続けます。

起動中は縦画面用の表示ページを`http://localhost:8080`で開けます。文字起こしは
表示専用WebSocket（ポート`8765`）でリアルタイムに反映されます。音声デバイス設定中は
現在の設定と選択可能なデバイスを表示し、受話器を置くと画面上の会話と設定表示を
すべて消します。レトロな額縁と紙の背景は常に残し、タイトル、通話状態、表示サーバーの
接続状態は待機中・通話中とも表示しません。会話の吹き出しには話者名を付けず、
文字だけを表示します。表示用WebSocketが切断された場合は画面中央に`・・・`を表示し、
1秒ごとに自動再接続します。再接続できると`・・・`は自動的に消えます。

デフォルトではプログラム起動時にChromiumを検出し、表示ページをキオスクモードで
自動的に開きます。自動起動しない場合は`.env`で`DISPLAY_KIOSK=false`にします。
自動検出できない場合は、`DISPLAY_KIOSK_BROWSER=/usr/bin/chromium`のように実行ファイルを
指定できます。Chromiumが見つからなくても電話アプリ本体はそのまま動作します。

会話中は、GPT-Liveから届いた文字起こしを内部で連結し、`参加者:`、`AI:`として
文章単位でコンソールへ表示します。受信を始めた時点では`文字起こし中`と表示し、
句読点を受信するか、文字の受信が1秒間止まった時点で、まとまった文章を表示します。
音声Base64やその他のWebSocketイベントは表示しません。通信や音声処理に異常がある場合だけ、
原因を確認できる短いエラーログを表示します。

モックGPIOでは、`u`で受話器を上げ、`d`で置き、`0`～`9`でダイヤル入力を再現できます。音声とGPT-Liveは実際に接続されるため、APIキーとUSB音声デバイスが必要です。

## 実機接続

BCM GPIO番号で次のように接続します。接続前に、対象が外部電圧のない機械接点であることをテスターで確認してください。

```text
GPIO17 ── フックスイッチ ── GND
GPIO26 ── ダイヤル接点 ─── GND
```

初期設定では内部プルアップを使います。フックの論理が逆なら`HOOK_LIFTED_WHEN_LOW`を変更してください。

USBデバイスは次のコマンドで確認できます。

```bash
arecord -l
aplay -l
python -m sounddevice
```

USB音声デバイス向けの既定値は`AUDIO_DEVICE_SAMPLE_RATE=48000`です。
デバイスが指定形式に対応せず`Invalid sample rate`や`Sample format not supported`に
なる場合は、そのデバイスが対応するサンプルレートを指定します。
GPT-Liveとの通信は24,000 Hzのまま、入出力時に自動変換されます。

受話器とベルに別々のスピーカーを使う場合は、`python -m sounddevice`で番号を確認し、
`.env`へそれぞれ設定します。

```env
AUDIO_OUTPUT_DEVICE=1
AUDIO_DEVICE_SAMPLE_RATE=48000
AUDIO_OUTPUT_VOLUME=1.0
BELL_OUTPUT_DEVICE=2
BELL_DEVICE_SAMPLE_RATE=48000
BELL_VOLUME=0.7
AUDIENCE_OUTPUT_DEVICE=3
AUDIENCE_DEVICE_SAMPLE_RATE=48000
AUDIENCE_VOLUME=0.7
```

観客用出力には、受話器で再生するGPT-Live音声・保留音・話中音と、
ベル音の両方が複製されます。`AUDIENCE_OUTPUT_DEVICE`が空欄の場合は無効です。

音声設定画面では、ダイヤルの`0`〜`3`で入出力デバイスを選び、
`4`〜`6`で受話器・ベル・観客用の音量を選びます。音量は続けて
`0`（消音）〜`9`（最大）を回して設定します。

## テスト

```bash
python -m unittest discover -s tests -v
```

このテストはGPIO、USB受話器、OpenAI APIを使わずに実行できます。

## 注意

- 黒電話を電話回線へ接続しないでください。
- Raspberry PiのGPIOへ5Vを入力しないでください。
- APIキーをソースコードやGitへ保存しないでください。
- 初期版のダイヤル入力はログに記録するところまでです。会話中の機能割り当ては今後追加します。
